# V3 release and return requirement consumer

The Docker checker consumes the single Updater-owned descriptor/evaluator
`IU-WS6-01/RELEASE-RETURN/1`, using Contracts revision 1 at commit
`d32ea3514b1c1010391caae0348b0ff9e751f447`. It does not duplicate CC01/CC02
membership/vector rules or infer qualification from the existing v2 manifest.
`scripts/generate-release-manifest.py` and v2 source-lock semantics are preserved.

The caller supplies an explicit local evaluator path, SHA256, exact Updater
source commit, descriptor file and positive byte/depth budgets. The consumer
checks the executable digest and non-authority handshake, then passes metadata
to the offline evaluator. It never invokes Docker Engine, a registry, image
publication, update, restore, v2 startup, Recovery, credentials or a Provider.
CI checks out the reviewed Updater commit, builds this executable and records
both repository commit/tree identities. The handshake is not a signed build
attestation or proof of actual storage/restore qualification.

| Evaluator state | Display/operational meaning |
| --- | --- |
| StructurallyCoherent | Declared tuples/references cohere; actual qualification is unconnected. |
| NeedsEvidence | Preserve missing/unknown facts and original Effect/Attempt; no blind retry. |
| NeedsDecision | Keep unadopted model/profile decisions pending; no default storage/layout. |
| Contradiction | Refuse the conflicting descriptor; preserve original evidence. |

All four emitted fields `authorizes_mutation`, `reusable_for_commit`,
`production_qualified` and `common_restore_freshness_proven` must be false.
The checker refuses a response that promotes any of them. Matching values do
not detect simultaneous restoration of CP, ledger and all comparison roots.
An unknown first-new-business-effect marker maps to RET-S3; PRE-business backup
or compatibility booleans do not establish POST-business/formal-v2-return scope.

`testdata/v3-release-requirements/conformance.json` is the exact copy of Updater's
18-case literal oracle, not expected output generated by the implementation.
`tools/run-v3-release-requirements-tests.py` requires all 5 reviewed roots and
18 vector subcases, with Skip=0/Fail=0, through the actual evaluator executable.
The new workflow is pull-request-only, contents-read-only and test-only.
Existing manifest/Contracts CI and every release/publish workflow are unchanged.

These checks prove a synthetic metadata connection. No actual image/host/codec/
storage/Provider/Recovery qualification, native arm64 run, production deployment
or formal-v2-return drill is claimed. All required remaining functions and
qualification work remain prerequisites for the first full v3 release.
